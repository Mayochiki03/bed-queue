# 06 · ข้อมูลตัวอย่าง (mock) — ไว้ให้หัวหน้าลองเล่น และลบก่อนขึ้น production

ข้อมูลตัวอย่างทำให้หน้าจอไม่ว่างเปล่าตอนสาธิต: มีคิวรอ/เรียกแล้ว/รอนัดวัน/ยืนยันแล้ว/ยกเลิก กระจายตามสีและโรงพยาบาล มีผู้ลงทะเบียนรออนุมัติให้ลองกดอนุมัติ/ไม่อนุมัติ
**ใช้กับเครื่อง dev เท่านั้น** — ระบบไม่ยอมสร้างบน production (`NODE_ENV=production`)

---

## 1) ก่อนเริ่ม: ตรวจว่าใช้ฐานข้อมูลถูกตัว

เปิด `.env` ดูบรรทัด `DB_NAME` — ต้องเป็น `bed_queue` (**ห้ามเป็น `bed_queue_test`** ซึ่งเป็นฐานของ `npm test` ที่ถูกลบทุกครั้งที่รัน ระบบจะไม่ยอมเริ่มถ้าตั้งผิด)

## 2) คำสั่ง (รันที่โฟลเดอร์นอกสุดของโปรเจกต์)

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run mock` | สร้างข้อมูลตัวอย่าง (ถ้ามีอยู่แล้วจะไม่ทับ — ให้ใช้ `--force`) |
| `npm run mock -- --force` | ลบชุดเดิมแล้วสร้างใหม่ (วันเวลาเลื่อนตามวันนี้ ข้อมูลหน้าตาเดิม) |
| `npm run mock:status` | ดูว่าฐานข้อมูลนี้มีข้อมูลตัวอย่างเหลือเท่าไร |
| `npm run mock:clear` | **ลบข้อมูลตัวอย่างทั้งหมด** แล้วรายงานว่าเหลืออะไร |

ลบได้อีกทางที่เมนู **นักพัฒนา → ผู้ขอจำลอง → ล้างข้อมูลจำลอง** (ทำงานเหมือน `mock:clear`)

## 3) ในชุดข้อมูลมีอะไร

| อะไร | จำนวน | ดูได้ที่ |
|---|---|---|
| ผู้ขอจำลอง (`MOCK-…`) | 12 คน กระจาย 8 รพ. | บอร์ดคิว / ประวัติคำขอ |
| คำขอเตียง | 60 รายการ: รอคิว 14 · เรียกแล้ว 5 (2 เกินเวลา) · รอนัดวัน 4 · ยืนยันแล้ว 25 · ไม่ยืนยัน 6 · ยกเลิก 6 | บอร์ดคิว · ประวัติคำขอ · Dashboard |
| ผู้ลงทะเบียนตัวอย่าง (`DEMO-…`) | 9 คน: **รออนุมัติ 5** · อนุมัติแล้ว 2 · ไม่อนุมัติ 2 (1 คนมีเหตุผล) | สมาชิก รพ. (แถบฟ้าบนบอร์ดคิวจะเตือน) |
| รพ. ตัวอย่าง | 8 แห่ง รหัส `99001`–`99008` ต่อท้าย "(ตัวอย่าง)" เขตสุขภาพ 12 | ข้อมูลหลัก → โรงพยาบาล |

ชื่อ/เบอร์เป็นของสมมติ (นามสกุล "ตัวอย่าง", เบอร์ `081000xxxx`) **ระบบไม่ส่ง LINE จริงหาใครเลย** (ข้ามผู้ขอจำลองและผู้ลงทะเบียนตัวอย่างทั้งหมด — ในประวัติแจ้งเตือนจะขึ้น "ข้าม")

## 4) สคริปต์ให้หัวหน้าลองเล่น (ประมาณ 10 นาที)

1. **หน้าภาพรวม (Dashboard)** — ดูตัวเลข/กราฟ ลองเปลี่ยนช่วงเวลา (วันนี้ / 7 / 30 วัน / กำหนดเอง) และกด "ส่งออก Excel"
2. **บอร์ดคิว** — สลับ "รวมทุกสี / แยกตามสี" · กด **เรียกคิว** ที่เคสแรก (ต้องเลือกวันที่เตียงว่าง) · ที่การ์ด "เรียกแล้ว" ลองกด **ยืนยัน** · ที่การ์ด "รอนัดวัน" กด **บันทึกวันที่**
3. **เพิ่มคำขอ** (ปุ่มมุมขวาบน) — ลองกรอกแทนผู้ขอที่โทรมา เลือกวันเวลาย้อนหลังได้
4. **สมาชิก รพ.** — กด **อนุมัติ** ผู้ที่รออนุมัติ 1 คน และกด **ไม่อนุมัติ** อีกคน (ลองใส่เหตุผล)
5. **ภาพรวมแบบไม่ล็อกอิน** — เปิดสวิตช์ที่ ตั้งค่าระบบ → Dashboard แล้วเปิด `http://<IP เครื่อง>:4002/admin/overview` ในหน้าต่างไม่ระบุตัวตน (ดูอย่างเดียว) ลองปุ่ม "จอใหญ่" / "เต็มจอ"
6. **ข้อความแจ้งเตือน / บันทึกการใช้งาน** — ดูว่าทุกการกดถูกจดไว้ ใครทำอะไรเมื่อไร

> ระหว่างทดสอบ ข้อมูลจะเปลี่ยนตามที่กด (เช่น ยืนยันไปแล้วกลับไปรอคิวไม่ได้) ถ้าอยากเริ่มใหม่: `npm run mock -- --force`

## 5) ✅ เช็กลิสต์ก่อนขึ้น production

```powershell
npm run mock:status     # ดูว่ามีข้อมูลตัวอย่างค้างไหม
npm run mock:clear      # ลบ (ทำบนฐานข้อมูลที่จะใช้งานจริงด้วย ถ้าเคยสร้าง mock ไว้)
npm run mock:status     # ต้องขึ้น "ไม่มีข้อมูลตัวอย่าง"
```

- ถ้าข้ามขั้นนี้ ตอนเปิดระบบบน production จะมีข้อความเตือนสีเหลืองในหน้าจอคำสั่งว่ามีข้อมูลตัวอย่างค้างอยู่ (ไม่บล็อกการเปิด แต่ควรลบ)
- `mock:clear` ลบเฉพาะข้อมูลตัวอย่าง: ผู้ขอจำลอง/ผู้ลงทะเบียนตัวอย่าง + คำขอและประวัติของพวกเขา + รพ. ตัวอย่าง `99001`–`99008` ที่ไม่มีใครอ้างอิงแล้ว
  **ไม่แตะ** คำขอที่เจ้าหน้าที่บันทึกเอง, รพ. จริงที่นำเข้าจาก Excel, ผู้ใช้งาน, ตั้งค่า, Dashboard
- สิ่งที่ยังต้องจัดการเอง: ลบบัญชีทดสอบที่เจ้าหน้าที่สร้างไว้ (หน้า ผู้ใช้งาน) · เปลี่ยนรหัส `admin` · ปิดสวิตช์ "ดู Dashboard โดยไม่ล็อกอิน" ถ้าไม่ต้องการ · ดู [database/README.md](../database/README.md) เรื่องสำรองข้อมูล
- เคยรัน mock รุ่นเก่า (ก่อน 0.10.2) ไว้: รุ่นเก่าสร้าง รพ. ด้วยรหัสจริง (`11206`, `10711` ฯลฯ) ซึ่ง `mock:clear` รุ่นใหม่จะไม่ลบ (กันลบ รพ. จริง) — ถ้าไม่ต้องการ ให้ลบเองที่หน้า ข้อมูลหลัก → โรงพยาบาล หรือนำเข้ารายชื่อจริงทับ

## 6) ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `มีผู้ขอจำลองอยู่แล้ว … ใช้ --force` | มีชุดเดิมอยู่ → `npm run mock -- --force` |
| ข้อมูลตัวอย่างหายหลังรัน `npm test` | `DB_NAME` ใน `.env` เป็น `bed_queue_test` → แก้เป็น `bed_queue` (ดู CHANGELOG 0.10.2) |
| บอร์ดเต็มไปด้วยเคส "เกินเวลา" | ตั้งใจให้มี 2 เคสเรียกแล้วเกิน 24 ชม. เพื่อโชว์การเตือน · ที่เหลือเกิดจากวันเวลาที่เลื่อนไปตามวันที่สร้าง ถ้าห่างหลายวันให้ `--force` ใหม่ |
| ห้ามสร้างข้อมูลตัวอย่างบน production | ตั้งใจ — ระบบกันไว้ |
