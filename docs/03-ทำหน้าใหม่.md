# 03 — ทำหน้าใหม่ (ก๊อปหน้าตัวอย่างแล้วแก้)

วิธีทำงานหลักของตัวกลางนี้: **เปิดหน้าตัวอย่างที่หน้าตาใกล้เคียงกับที่อยากได้ → ก๊อปทั้งโฟลเดอร์ → เปลี่ยนชื่อ → แก้ฟิลด์**
ตัวอย่างนี้ทำหน้า "สินค้า" (`product`) จากหน้าตัวอย่าง `hospital`

| อยากได้หน้าแบบ | ก๊อปจาก |
|---|---|
| ตาราง + เพิ่ม/แก้/ลบ + modal เลือกจากตาราง | `hospital` |
| อ่านอย่างเดียว (รายงาน / log) | `log` |

## ขั้นตอน

**1. ก๊อปโฟลเดอร์ (2 ที่)**
- `backend/src/pages/hospital` → `backend/src/pages/product`
- `frontend/src/pages/hospital` → `frontend/src/pages/product`
- `frontend/src/api/hospitalApi.ts` → `frontend/src/api/productApi.ts`

**2. เปลี่ยนชื่อ** ใน VS Code กด `Ctrl+Shift+H` (ค้นหาและแทนที่ทั้งโปรเจกต์ — เลือกเฉพาะโฟลเดอร์/ไฟล์ที่ก๊อปมา) เปิดปุ่ม "Preserve Case" (`AB`):

| ค้นหา | แทนที่ |
|---|---|
| `hospital` | `product` |
| `Hospital` | `Product` |
| `คู่ค้า` | `สินค้า` |

แล้วเปลี่ยนชื่อไฟล์ที่ยังขึ้นต้นด้วย `Hospital` (คลิกขวา Rename ที่ไฟล์ VS Code จะแก้ import ให้เอง)
และเปลี่ยนชื่อ migration ใน `ProductMigration.ts` ให้ใหม่กว่าเดิมและไม่ซ้ำ เช่น `20260201_product`

**3. แก้ฟิลด์ให้ตรงกับข้อมูลจริง** (ไล่จากข้อมูลออกมาหน้าจอ)

ฝั่งหลังบ้าน `backend/src/pages/product/`
1. `Product.ts` — Entity (หน้าตาข้อมูล)
2. `ProductDto.ts` — ช่องที่รับ + กติกาตรวจ (`fields`)
3. `ProductMigration.ts` — คอลัมน์ในตาราง
4. `ProductRepository.ts` — เงื่อนไขค้นหาใน `search()` (ถ้ามีตัวกรองอื่น)
5. `ProductService.ts` — กติกาธุรกิจ (เช่น ห้ามซ้ำ) *ปกติไม่ต้องแก้ถ้าไม่มีกติกาเพิ่ม*

ฝั่งหน้าเว็บ
1. `api/productApi.ts` — type `Product` (ชื่อฟิลด์ต้องตรงกับ backend) และตัวเลือก dropdown
2. `pages/product/ProductForm.tsx` — ช่องกรอก (`TextField` / `SelectField` / `RadioField` / `TextAreaField`)
3. `ProductTable.tsx` — `columns` (คอลัมน์ตาราง) และช่องกรอง
4. `ProductAdd.tsx` — `DEFAULTS` (ค่าเริ่มต้นของฟอร์ม)
5. `ProductEdit.tsx` — รายชื่อฟิลด์ใน `form.reset({...})`
6. `modal/ProductPickModal.tsx` — ถ้าไม่ใช้ modal เลือกจากตารางให้ลบไฟล์นี้ กับช่อง `PickerInput` ใน `ProductTable.tsx`

**4. ลงทะเบียนหน้า (ไฟล์ละบรรทัด)**
- `backend/src/pages/index.ts` → `import { productPage } from './product';` แล้วเพิ่มใน `pages`
- `frontend/src/config/routes.tsx` → `{ path: '/product/*', element: <ProductPage />, roles: ALL_STAFF }`
- `frontend/src/config/menu.ts` → เพิ่มบรรทัดเมนู `{ label: 'สินค้า', path: '/product' }`

**5. ตรวจ** `npm run check` (TypeScript) แล้ว `npm run dev` ลองเพิ่ม/แก้/ลบ — ตารางถูกสร้างให้เองตอนเปิดระบบ

## กติกาที่ต้องรักษาเมื่อแก้

- **ไม่ส่งข้อมูลหรือ id ทาง URL** — API ใหม่ทุกตัวเป็น `router.post('/ชื่อ', ...)` อ่านค่าจาก `req.body` (ตรวจด้วย DTO) และฝั่งหน้าเว็บเรียกผ่าน `api.post`
- เพิ่ม **หน้าย่อย** ในฟีเจอร์ (เช่น `/product/detail`) = เพิ่มไฟล์ + เพิ่ม `<Route>` ใน `ProductPage.tsx` ไม่ต้องแตะ `config/routes.tsx`
- **modal** ของหน้าไหนเก็บในโฟลเดอร์ `modal/` ของหน้านั้น ถ้าเป็น modal เลือกจากตารางให้ใช้ `components/SelectModal.tsx` ห่อไว้ (ดู `HospitalPickModal.tsx`)

## ปุ่มบันทึก/ลบ และหน้าจอมือถือ (ก๊อปจาก hospital แล้วอย่าลบส่วนนี้)

- **ถามยืนยันก่อนบันทึก:** ใน `HospitalAdd` / `HospitalEdit` หลังตรวจฟอร์มผ่านจะมี `popup.confirm(...)` ก่อนเรียก API (ปุ่มที่โฟกัสอยู่คือ "ยกเลิก" กด Enter รัว ๆ ก็ไม่บันทึก) ส่วนการลบถามยืนยันอยู่ใน `handleDelete` ของ `HospitalTable`
- **กัน Enter ส่งฟอร์ม:** `<form onKeyDown={noEnterSubmit}>` — Enter ในช่องกรอกบรรทัดเดียวจะไม่ทำอะไร (ในช่องหมายเหตุยังขึ้นบรรทัดใหม่ได้)
- **ตารางบนมือถือ:** คอลัมน์ที่รองลงมาให้ใส่ `className: 'hidden md:table-cell'` (ซ่อนต่ำกว่า 768px) หรือ `'hidden sm:table-cell'` (ต่ำกว่า 640px) — แต่คอลัมน์ "จัดการ" อย่าซ่อน
- ทดสอบหน้าใหม่ที่ความกว้าง 360px (เปิด DevTools → โหมดมือถือ) ว่าไม่มีอะไรล้นจอและกดปุ่มได้ครบ

## เมื่อ role เข้าหน้าได้ไม่เท่ากัน

ตั้ง `roles` ให้ตรงกันทั้งสองฝั่ง: `definePage({ roles: ['ADMIN'] })` ใน backend และ `roles: ['ADMIN']` ใน `routes.tsx` (backend คือตัวตัดสินจริง ส่วน frontend แค่ซ่อนเมนู/หน้า) เพิ่มชื่อ role ใหม่ที่ `backend/src/core/pages.ts` (`Role`, `ROLES`) และ `frontend/src/lib/session.tsx` (`Role`)

## หน้าที่ไม่ใช่ CRUD

ไม่ต้องบังคับใช้รูปแบบเดียวกัน: หน้าที่มี logic เฉพาะ (คำนวณ, อนุมัติหลายขั้น) ให้เขียน Controller / Service ของหน้าเองตามต้องการ (ชั้นไหนไม่ต้องใช้ก็ข้ามได้ เช่น หน้า `log` ไม่มี migration) แล้วเขียนหน้าจอเองด้วย component กลาง (`PageCard`, `Button`, `Fields`, `Popup`, `SelectModal`) — ระบบ login / สิทธิ์ / audit / รูปแบบ error ทำงานให้เหมือนหน้าอื่นทุกอย่าง
