# 01 — เริ่มต้นใช้งาน

## รันครั้งแรก

ต้องมีฐานข้อมูล MariaDB ก่อน (ระบบนี้ไม่มีฐานข้อมูลสำรองในตัว) — ทำตาม [database/README.md](../database/README.md) ครั้งเดียว แล้ว:

```powershell
npm install
npm run dev
```

- หน้าเว็บ: http://localhost:5173  ·  API: http://localhost:4000
- เข้าสู่ระบบ: `admin` / `ChangeMe!123` (เปลี่ยนที่ `ADMIN_PASSWORD` ใน `.env` **ก่อนรันครั้งแรก** — แอดมินถูกสร้างตอนฐานข้อมูลยังว่างเท่านั้น)
- ข้อมูลเก็บในฐานข้อมูล `bed_queue` บน MariaDB — อยากเริ่มใหม่หมด: `npm run db:reset -- --yes` (ลบข้อมูลทั้งหมด!)

> Windows PowerShell: ใช้ `;` แทน `&&` ถ้าต่อหลายคำสั่ง (PowerShell เวอร์ชันเก่าไม่รู้จัก `&&`)

## เปลี่ยนค่าตั้งต้น

```powershell
npm run setup
```
สร้าง `.env` (สุ่ม `JWT_SECRET` ให้) แล้วแก้ไฟล์นั้น — **ไฟล์ตั้งค่ามีไฟล์เดียวที่โฟลเดอร์นอกสุด** ทั้งหลังบ้านและหน้าเว็บอ่านจากที่เดียว

| ตัวแปร | ความหมาย |
|---|---|
| `APP_NAME`, `APP_THEME` | ชื่อระบบ, ธีมสี (`herb` / `ocean` / `rose` / `slate`) |
| `INTERNAL_PORT`, `PUBLIC_PORT`, `WEB_PORT` | พอร์ตหน้าเจ้าหน้าที่/API (4002, LAN) · พอร์ตที่ต่อ tunnel (4003) · หน้าเว็บตอนพัฒนา (5173) — พอร์ตชนให้เปลี่ยนที่นี่ที่เดียว |
| `DB_CLIENT` | `mariadb` (ค่าเริ่มต้น) / `mysql` / `postgres` |
| `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME` | ค่าตั้งต้น `127.0.0.1` `3306` `app` `app_password` `bed_queue` (ตรงกับ `database/init.sql`) — **production ต้องเปลี่ยนรหัสผ่าน** ระบบไม่ยอมเริ่มถ้ายังเป็นค่าตั้งต้น |
| `JWT_SECRET` | production ต้องตั้งยาว 32 ตัวอักษรขึ้นไป (`npm run setup` สุ่มให้) |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | แอดมินคนแรก |
| `AUTO_MIGRATE` | สร้างตารางตอนเปิดระบบ (เปิดตอนพัฒนา, ปิดตอน production) |

## สลับไปใช้ MySQL / PostgreSQL

ค่าเริ่มต้นคือ MariaDB (ดู `database/README.md`) ถ้าจะใช้ฐานอื่น: ตั้ง `DB_CLIENT=mysql` หรือ `postgres` (PostgreSQL ใช้พอร์ต `5432` และต้องสร้างฐานข้อมูล/ผู้ใช้เอง — ตัวอย่างอยู่ท้ายไฟล์ `database/README.md`) แล้ว `npm run dev` — ตารางและแอดมินคนแรกถูกสร้างให้เอง

กฎที่ทำให้สลับฐานได้: ใช้ knex query builder เท่านั้น ห้าม ENUM / SQL ดิบ / ฟังก์ชันเฉพาะฐาน (เช่น `NOW()`) — ตัวช่วยที่ต้องต่างกันตามฐานอยู่ใน `backend/src/core/db.ts` ที่เดียว วันที่-เวลาเก็บเป็นข้อความ ISO (UTC) เหมือนกันทุกฐาน

## ขึ้นใช้งานจริง (production)

```powershell
npm run build
$env:NODE_ENV="production"; $env:JWT_SECRET="...ยาว 32+ ตัว..."; $env:DB_PASSWORD="...รหัสจริง..."   # หรือตั้งใน .env
npm run migrate
npm start
```
`npm start` เปิด 2 พอร์ต: `INTERNAL_PORT` (หน้า `/admin` + API ทั้งหมด ใช้ใน LAN) และ `PUBLIC_PORT` (webhook + หน้าผู้ขอ ต่อ Cloudflare Tunnel) — ถ้าใช้ HTTPS ให้ตั้ง `COOKIE_SECURE=true`

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / ทางแก้ |
|---|---|
| หน้าเว็บขึ้น "ไม่สามารถเชื่อมต่อเซิร์ฟเวอร์" | API ไม่ได้รัน หรือ `INTERNAL_PORT` ใน `.env` ไม่ตรง — ดู log ฝั่ง `[api]` |
| `พอร์ต … ถูกใช้อยู่แล้ว` | ตั้ง `INTERNAL_PORT` / `PUBLIC_PORT` ใหม่ใน `.env` (หน้าเว็บตามให้เอง) |
| `ต่อฐานข้อมูลไม่ได้ ...` / `ฐานข้อมูลปฏิเสธการเข้าสู่ระบบ ...` / `ยังไม่มีฐานข้อมูลชื่อ ...` | ยังไม่ได้เปิด MariaDB / รหัสใน `.env` ไม่ตรง / ยังไม่ได้รัน `database/init.sql` — ทำตาม [database/README.md](../database/README.md) |
| Login ไม่ได้ทั้งที่รหัสถูก | แอดมินถูกสร้างครั้งเดียวตอนฐานว่าง — ถ้าเปลี่ยน `ADMIN_PASSWORD` ทีหลัง ให้ `npm run db:reset -- --yes` (ลบข้อมูลทั้งหมด) |
| `ฐานข้อมูลนี้มีประวัติ migration ที่ไม่ตรงกับโค้ดปัจจุบัน` | ใช้ฐานข้อมูลเก่าจากเวอร์ชัน/โปรเจกต์อื่น (เช่น อัปเดตตัวกลางทับของเก่า) — ข้อมูลทดลองให้ลบฐานข้อมูลแล้วสร้างใหม่ให้ว่าง (รัน `database/init.sql`) แล้วรันอีกครั้ง |
