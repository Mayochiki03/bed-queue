# ระบบคิวขอเตียง (bed-queue)

ระบบรับคำขอเตียงผู้ป่วยจากโรงพยาบาลอื่น แทนการกรอก Google Form: ผู้ขอส่งคำขอ ระบบเรียงคิว เจ้าหน้าที่เลือกเรียกเคสตามสีเตียงที่ว่าง แล้วแจ้งผู้ขอให้ยืนยันส่งตัว
ระบบ **ไม่ได้จัดการจำนวนเตียงว่าง** (เหมือน Google Form + คิว) — เจ้าหน้าที่ตัดสินใจเองว่าจะเรียกเคสไหนก่อน

สร้างบนชุดตัวกลาง [App-Core](https://github.com/Mayochiki03/App-Core) (โครงชั้นหลังบ้าน, ล็อกอิน, audit log, ชุด component หน้าเว็บ) ที่ใช้ร่วมกับระบบอื่น

- **TypeScript** ทั้งหน้าเว็บและหลังบ้าน · **React + Tailwind** · **Express + knex** · **MariaDB** (ไม่มี SQLite)
- สิทธิ์ 3 ระดับ: เจ้าหน้าที่จัดคิว < ผู้ดูแล < นักพัฒนา · ทุกการเพิ่ม/แก้/ลบมี popup ยืนยัน · ใช้ได้บนมือถือ (360px)
- ค่าลับ (LINE token/secret) เก็บในฐานข้อมูลแบบเข้ารหัส AES-256-GCM

## สถานะการพัฒนา

| รอบ | เนื้อหา | สถานะ |
|---|---|---|
| 1 | โครงระบบ, ผู้ใช้/สิทธิ์, โรงพยาบาล, ข้อมูลหลัก (สี/สารเสพติด/เหตุผล), ตั้งค่าระบบ, หน้าหลัก Dashboard, ตารางคำขอ | เสร็จ (v0.1.0) |
| 2 | บอร์ดคิว (รวม/แยกสี), เรียกคิว/ยืนยัน/ปฏิเสธ/ยกเลิก, เพิ่ม-แก้คำขอโดย admin, โอนเคสให้ผู้ขอคนอื่นใน รพ. เดียวกัน | วางแผน |
| 3 | Dashboard เต็ม, นำเข้า/ส่งออก Excel | วางแผน |
| 4 | หน้าผู้ขอ (LINE LIFF), แจ้งเตือน LINE, เมนูนักพัฒนา (ตั้งค่า LINE, โหมด LOCAL/DEV_TUNNEL/PRODUCTION) | วางแผน |

รายละเอียดแต่ละเวอร์ชันดู [CHANGELOG.md](CHANGELOG.md)

## เริ่มใช้

**1) เตรียมฐานข้อมูล MariaDB (ครั้งเดียว)** — ดู [database/README.md](database/README.md)
(มี Docker: `docker compose -f database/docker-compose.yml up -d`) ฐานที่ใช้: `bed_queue` (ข้อมูลจริง) และ `bed_queue_test` (เทสต์เท่านั้น เทสต์ลบตารางทุกครั้ง)

**2) สร้าง `.env` แล้วรัน**

```powershell
npm install
npm run setup     # สร้าง .env พร้อมสุ่ม JWT_SECRET และ APP_SECRET_KEY
npm run dev
```

เปิด http://localhost:5173 — เข้าสู่ระบบด้วย `admin` / `ChangeMe!123` (เป็นสิทธิ์นักพัฒนา ควรเปลี่ยนรหัสทันที)

> `APP_SECRET_KEY` ห้ามทำหายหรือเปลี่ยน ไม่เช่นนั้นค่าลับที่เข้ารหัสไว้ในฐานข้อมูลต้องกรอกใหม่ · ขึ้นใช้งานจริงต้องตั้งค่านี้เองและเปิด HTTPS (`COOKIE_SECURE=true`)

## ส่วนของระบบนี้

```
backend/src/pages/
  setting/      ตั้งค่าระบบในฐานข้อมูล (นิยามค่าที่ SettingDefs.ts)
  hospital/     โรงพยาบาลต้นทาง (ชื่อ + รหัส 5 หลัก)
  lookup/       ข้อมูลหลัก: สี, ประเภทสารเสพติด, เหตุผลการส่งต่อ
  user/         ผู้ใช้งาน (ADMIN ขึ้นไป)
  request/      ตารางคำขอ/ผู้ขอ/ประวัติเหตุการณ์/ส่งตัว/ข้อความ LINE (API บอร์ดคิวมารอบ 2)
  dashboard/    ตัวเลขและกราฟสรุปของหน้าหลัก
  log/          ดูบันทึกการใช้งาน
frontend/src/
  pages/        Home (Dashboard), hospital, lookup, user, setting, account (เปลี่ยนรหัสผ่าน), log
  components/   ชุด component กลาง + charts/ (TrendChart, StackedBars, HBars) + EditorPage (ฟอร์มเพิ่ม/แก้มาตรฐาน)
  hooks/        useTableData, useLookups, useEditId
```

โครงชั้นของแต่ละหน้า (Entity / Dto / Repository / Service / Controller / Migration) และวิธีทำหน้าใหม่ อ่านที่ `docs/` (เอกสารจากชุดตัวกลาง ใช้ตัวอย่างหน้า "hospital")

**กติกาความปลอดภัย:** ไม่ส่ง id หรือข้อมูลใด ๆ ทาง URL (path / query) — ทุก API เป็น POST ส่งใน body และหน้าแก้ไขรับ id ผ่าน state ของ router · ข้อมูลผู้ป่วยเป็นข้อมูลสุขภาพ (PDPA) ควรปรึกษาผู้รับผิดชอบข้อมูลของโรงพยาบาลก่อนใช้งานจริง

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | รันหลังบ้าน + หน้าเว็บ (รีโหลดเอง) |
| `npm run check` | ตรวจ TypeScript ทั้งสองฝั่ง (รันก่อน commit) |
| `npm test` | ทดสอบ API กับฐาน `bed_queue_test` (ไม่แตะข้อมูลจริง) |
| `npm run build` / `npm start` | build หน้าเว็บ / รันแบบ production |
| `npm run migrate` / `migrate:status` | สร้าง/ดูสถานะตาราง |
| `npm run db:reset -- --yes` | ลบข้อมูลทั้งหมดแล้วสร้างตารางใหม่ (ต้องใส่ `--yes` เอง) |
